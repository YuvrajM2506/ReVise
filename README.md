# ReVise — AI Code Review Agent with Hindsight Memory

> **Memory is not a feature bolted onto an LLM wrapper — it is the product.**
> ReVise reviews code changes against your team's own history: past PR reviews, pipeline
> failures, incidents and post-mortems stored in [Hindsight](https://hindsight.vectorize.io/),
> so a finding can cite the outage it would have caused.

## What ReVise does

Given a code change, ReVise:

1. **Retrieves** relevant engineering memory (semantic + keyword + causal/temporal) scoped to the
   service and focus area being changed.
2. **Reasons** over the change *together with* those dated memories using a Groq-hosted model
   under a strict JSON schema, citing memory IDs in its findings.
3. **Persists** the run so it appears in the timeline, the reports list and the memory pulse, and
   can be **written back** to memory when a human reports the real outcome.

The differentiator is step 1 and the write-back loop: a stateless reviewer can only tell you a
lock is risky; ReVise can tell you which incident it caused last time, with the run ID.

## Architecture

```
        Browser (Next.js App Router, React client components)
                       │  fetch /api/*
                       ▼
   ┌───────────────────────────────────────────────────────────────────┐
   │ Next.js route handlers (frontend/src/app/api/**)                  │
   │                                                                   │
   │  /api/github/analyze    fetch PR files + diff from GitHub         │
   │  /api/analyze           analyse a raw code snippet                │
   │  /api/teach             write an outcome back into memory         │
   │  /api/aider/*           proxy to the Python pairing service       │
   └───────────────┬───────────────────────────────┬───────────────────┘
                   │                               │
   1. recall       │                               │  3. persist
      (lib/hindsight.ts)                          │     (lib/storage.ts)
                   ▼                               ▼
   ┌───────────────────────────┐        ┌─────────────────────────────┐
   │ Hindsight Cloud REST API  │        │ data/app_state.json         │
   │  POST /memories/recall    │        │ runs · memories · timeline  │
   │  POST /memories           │◄───────│ standards · guardrails      │
   │  GET  /config   (health)  │        │ diagnostics                 │
   └───────────────────────────┘        └─────────────────────────────┘
                   │
   2. reason:      │  (lib/groq.ts) the retrieved memories are injected into
      retrieved    │  the prompt; primary + fallback model chain with
      memories are ▼  exponential backoff and strict JSON schema output
              Groq Cloud LPU API ──► findings · risk score · memory citations
```

Every stage degrades instead of failing: if Hindsight is unreachable the retrieval falls back to a
local scorer over `data/app_state.json`; if Groq is unconfigured or exhausted, evaluation falls
back to the deterministic simulator. See [Live vs simulated behaviour](#live-vs-simulated-behaviour).

## Configuration

Two environment files exist, and they are read by different processes:

| File | Read by | Why |
| :--- | :--- | :--- |
| `frontend/.env.local` | Next.js (`frontend/`) | All analysis, memory and GitHub behaviour. |
| `.env.local` (repo root) | The Aider service | `aider-service/main.py` explicitly loads `../.env.local`. |

If you want both the web app and the pair programmer working, put your LLM key in **both** files.

| Variable | Used by | Default | Notes |
| :--- | :--- | :--- | :--- |
| `GROQ_API_KEY` | frontend, aider-service | *(unset)* | Without it the evaluator uses the simulator. |
| `GROQ_PRIMARY_MODEL` | frontend | `openai/gpt-oss-120b` | First candidate. |
| `GROQ_FALLBACK_MODEL` | frontend | `qwen-2.5-32b` | Tried before the three built-in fallbacks. |
| `HINDSIGHT_API_KEY` | frontend | *(unset)* | Only used when it starts with `hsk_`. |
| `HINDSIGHT_BANK_ID` | frontend | `acme-platform` | Default memory namespace. |
| `HINDSIGHT_PROJECT_ID` | frontend | *(unset)* | Alternative alias for the bank id. |
| `HINDSIGHT_BASE_URL` | frontend | `https://api.hindsight.vectorize.io` | |
| `AIDER_SERVICE_URL` | frontend | `http://localhost:8001` | |
| `AIDER_MODEL` | aider-service | provider default (`gpt-4o`, …) | Passed to Aider as `--model`. |
| `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GROQ_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY`, `DEEPSEEK_API_KEY` | aider-service | *(unset)* | First valid key wins; validated against the provider before each run. |
| `GITHUB_TOKEN` | — | — | **Ignored.** GitHub access is anonymous by design; see limitations. |

## Quick start

Full step-by-step instructions, the demo script and troubleshooting live in **[SETUP.md](SETUP.md)**.
The short version:

```bash
# 1. Web app
cd frontend
npm install
cp ../.env.example .env.local     # add your GROQ_API_KEY / HINDSIGHT_API_KEY
npm run seed                      # reset local demo state
npm run dev -- -p 3000            # http://localhost:3000

# 2. Pair programmer (optional, separate terminal)
pip install -r aider-service/requirements.txt
pip install -r aider-source/requirements.txt
cd aider-service && uvicorn main:app --port 8001 --reload
```

Pass `-p 3000` explicitly: if your shell already defines `PORT` (some agent harnesses set
`PORT=0`), `next dev` binds a random ephemeral port instead.

## Demo walkthrough (verified)

This is what the current UI actually does — not an aspirational script. All memory counts and
scores below come from the seeded dataset (`frontend/src/lib/seed-data.ts`).

| # | Go to | Do | What you should see |
| :--- | :--- | :--- | :--- |
| 1 | `/dashboard` | Land on Home | Seeded posture: the three seeded runs — `PR #167: Add customer-region analytics` (HIGH RISK), `RUN-889: Migration timeout` (LEARNED) and `INC-024: Checkout latency` (RESOLVED). |
| 2 | `/github-review` | Paste a **real public** PR URL, e.g. `https://github.com/physicshub/physicshub.github.io/pull/391` | A live GitHub diff is fetched, evaluated and scored (e.g. `RISK 79 / 100 · HIGH RISK`) with findings naming real files and memory citations. |
| 3 | `/github-review` | Paste `owner/repo PR 12` for a **private or missing** repo | An explicit error — `GitHub resource not found (404) … public repositories anonymously` — and **no run is stored**. |
| 4 | `/memory` | Browse the memory library | 12 seeded memories, including the four linked ones for orders-service: `PR #142`, `RUN-889`, `INC-024`, `PM-024`. |
| 5 | `/timeline` | Walk the causal chain | `PR #142 warning → RUN-889 rollback → INC-024 SEV-2 incident → PM-024 playbook → PR #167 prevented`. |
| 6 | `/standards` | Open Team Standards | Standards inferred from those incidents (e.g. `STD-001` zero-downtime PostgreSQL schema changes). |
| 7 | `/teach` | Describe an outcome and save | The outcome is retained and reported back as an added/reinforced memory. |
| 8 | `/pair-programmer` | Run a session (needs port 8001) | Aider works in a throwaway clone, guided by injected memories, and returns the real unified diff. |

To seed a **risk comparison**, post the same change twice with `memory_enabled` toggled — the API
supports it even though the current UI always sends `true`:

```bash
curl -s localhost:3000/api/analyze -H 'content-type: application/json' -d '{
  "pr_title": "PR #167: Add customer-region analytics",
  "service": "orders-service",
  "focus_areas": ["Unsafe DB migration"],
  "file_name": "migration_v167.sql",
  "language": "PostgreSQL",
  "code_snippet": "ALTER TABLE orders ADD COLUMN customer_region TEXT NOT NULL;\nCREATE INDEX idx_orders_region ON orders (customer_region);",
  "memory_enabled": true
}'
```

Always send a `code_snippet`: `/api/analyze` does not reject an empty one, so a request without it
will produce a confident review of nothing.

## How memory actually works

`frontend/src/lib/hindsight.ts` is the whole memory client.

**Retrieval** — `recallMemories(query, filters, bankId)`:

1. If `HINDSIGHT_API_KEY` starts with `hsk_`, `POST {HINDSIGHT_BASE_URL}/v1/default/banks/{bankId}/memories/recall`
   with a 4-second timeout, requesting `pr_review`, `pipeline_failure`, `incident`, `post_mortem`
   and `outcome_feedback` memories.
2. If that yields nothing (or throws), a local multi-strategy scorer ranks `store.memories` by
   service match, focus-area match, semantic term overlap, keyword/BM25-ish weighting and graph
   adjacency — the same id-space the demo cites (`MEM-PR-142`, `MEM-RUN-889`, …).

**Write-back** — `retainMemory(params)` posts to `/v1/default/banks/{bankId}/memories` *and* writes
locally, detecting whether the outcome reinforces an existing pattern or forms a new one
("Reinforced existing pattern" vs "New pattern detected").

**Health** — `checkHindsightHealth()` probes `GET /v1/default/banks/{bankId}/config` and reports
round-trip latency.

**Bank resolution** for a pull-request review is, in priority order: an explicit `bankId` from the
request → `HINDSIGHT_BANK_ID` → `"<owner>/<repository>"`.

**Local state** — `frontend/src/lib/storage.ts` keeps `data/app_state.json` (path derived from
`process.cwd()`, so it must run from `frontend/`) with an in-memory cache and `writeFileSync`
persistence: runs, memories, timeline, standards, guardrails and diagnostics.

## AI Pair Programmer (Aider)

The workspace at `/pair-programmer` talks to a small FastAPI service that runs
[Aider](https://aider.chat) non-interactively inside a sandbox, with retrieved memories injected
into the prompt. Details and the service contract are documented in
[`aider-service/README.md`](aider-service/README.md).

```bash
cd aider-service && uvicorn main:app --port 8001 --reload
```

- `GET /health`, `POST /health` — verifies a configured LLM credential **against the live provider API**
  (OpenAI, Anthropic, Groq, Gemini, OpenRouter or DeepSeek, in that order). No canned responses.
- `POST /run` — accepts `{repo_url, task, target_files[], memory_context[]}`; depth-1 clones a remote
  URL (or copies a local path) into a temp directory, runs Aider with `--yes-always
  --no-auto-commits` and a 240-second timeout, and returns the real unified diff.

## Live vs simulated behaviour

ReVise is built to demo without credentials, which means some paths are honest fallbacks rather
than live calls. What you are looking at:

| Behaviour | Live when | Fallback when |
| :--- | :--- | :--- |
| Memory retrieval | `HINDSIGHT_API_KEY` starts with `hsk_` and the bank answers within 4s | Local scorer over `data/app_state.json`. A successful-but-empty cloud response also falls through, silently. |
| Evaluation | `GROQ_API_KEY` set to a valid `gsk_` key | Deterministic simulator in `lib/groq.ts` (`model_used: simulator/gpt-oss-120b`). |
| PR files + diff | Always live (anonymous GitHub) | Never — an unreadable diff now aborts with `502` instead of guessing. |
| Pair programmer | A valid LLM key is visible to the service | `/run` returns `success: false` with the credential error. |
| Memory/timeline/standards pages | Their `/api/*` endpoints respond | Bundled `revise-ui/mocks/data.ts` samples. |

## Known limitations

- **GitHub is anonymous.** Public repositories only (private ones return 404/403), roughly
  60 requests/hour per IP with two calls per review, and **review comments are never posted back**.
  `GITHUB_TOKEN` is deliberately ignored.
- **The memory ON/OFF comparison is API-only.** `/api/analyze` and `/api/github/analyze` honour
  `memory_enabled`, but the UI always sends `true`; the landing page's side-by-side comparison is
  illustrative.
- **Report headers show `0 files · 0 lines changed`.** `mapRunToReview` in
  `revise-ui/services/revise.ts` hardcodes those counters even though the API returns real ones.
- **Sidebar counters are static.** See the status-pill caveat under [HTTP API](#http-api).
- **Pricing copy is incomplete.** Tier amounts are blank in both `frontend/src/app/pricing/page.tsx`
  and [REVENUE_MODEL.md](REVENUE_MODEL.md).
- **State is a single JSON file, last-writer-wins.** Concurrent writes to `data/app_state.json` can
  lose a run; there is no locking.
- **`frontend/src/components/` is dead code** retained from an earlier UI iteration.
- **`/api/analyze` accepts an empty `code_snippet`.** Unlike the GitHub route (which refuses to score
  a diff it could not fetch), the snippet endpoint will happily evaluate nothing and return a risk
  score. Always send `code_snippet`.

## Troubleshooting

Common failure modes and fixes are in **[SETUP.md → Troubleshooting](SETUP.md#7-troubleshooting)**.
The most frequent ones:

| Symptom | Cause | Fix |
| :--- | :--- | :--- |
| Every route returns `500`, log says *"stream did not contain valid UTF-8"* | A source file was saved in a non-UTF-8 encoding | Re-save the file as UTF-8 (this exact failure came from stray `0x95` bytes in `pricing/page.tsx`). |
| `next dev` starts on a random port | `PORT` is set in the environment (agents often set `PORT=0`) | `npm run dev -- -p 3000` |
| Env vars appear ignored | `.env.local` is at the repository root | Move/copy it to `frontend/.env.local` |
| Nothing updates after `npm run seed` | The script wrote to the root `data/` while the app reads `frontend/data/` | Run it from `frontend/` (`cd frontend && npm run seed`) |
